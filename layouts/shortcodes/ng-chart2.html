{{- /* ng-chart2 — an interactive NeilGarratt.com chart, INLINE (no iframe). A fork of ng-chart for the rail performance project, namespaced apart from it. BOTH engines publish to fixed filenames in this site, so they must not share any: this one ships /js/ngc2-*.js and /css/ngc2.css, the crime charts ship /js/chart-core.js, /js/charts.js, /js/charts-live.js and /css/ng-chart.css. Changing a name here without changing SITE_ASSETS in the rail project's chartkit/interactive.py will silently serve a stale engine. What the fork adds over ng-chart: - a LINE chart type in the live engine, for series too long to be bars (rail punctuality is ~160 four-week periods, not 13 years) - dimension names read from the spec rather than hardcoded, so the reducer no longer has to know what a dimension means - all display English moved into the spec's `strings` block Why inline rather than an iframe: the 3D vizzes need isolation because WebGL does. 2D SVG does not, and inline buys a lot — responsive for free, inherits the fonts and CSS variables main.css has already loaded, text stays selectable and keyboard-reachable, no click-shield, no fixed aspect ratio. Progressive enhancement, not a fallback: - The spec carries `bakedSvg`, the initial view pre-rendered by the STATIC engine at build time. That goes straight into the page, so a reader with JavaScript off — or a crawler, or a feed reader — gets a complete, correct, house-styled chart rather than an empty box. - ngc2-live.js then replaces it at IDENTICAL geometry (both engines read GEOM from ngc2-core.js) and reveals the controls. No flash, no layout shift, no dead buttons if the script never arrives. Data lives in data/charts/.json and is inlined at BUILD time, so a data refresh is a page change — no ?v= cache-buster to bump, unlike the 3D embeds.
