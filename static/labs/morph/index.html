Geography-morph workbench

This is a temporary prototype workbench for morphing between geography levels on the census map.

  • v0/ — minimal harness: split/merge value-morph on the OA basis (buttons, duration/easing controls, HUD)
  • v1/ — full census map with the curtain replaced by the morph (?morph=0 restores the curtain; ?hud=1 overlay)
  • v2/ — boundary-warp experiment: wards crack apart out of a borough block and heal back. Two verdicts. deck.gl's own transitions cannot tween getPolygon here — declaring one blanks the layer outright, silently (?postrans=1 reproduces it). Driving the warp from requestAnimationFrame instead does animate it, at ~25–46 fps. Outlines and values cannot move at the same time, so each choreography plays them as separate beats. Stills of the crack: ?s0=0.92, ?s0=0.8. Numbers in tools/morph-lab/captures/v2/RESULTS.txt.
  • v3/ — the warp on the GPU, and v2's three beats collapse into one. A custom deck.LayerExtension adds one per-vertex ring-centroid attribute and one morphT uniform and injects at vs:DECKGL_FILTER_GL_POSITION; the position attribute deck.gl blanked on is never written after the first draw, so there is no re-tessellation, and the value transition runs concurrently with the crack. Measured: the crack at 99.8% of full while the values sit 30% across, in the same frame — where v2's CPU path left the values at 29% by the 84% mark; ~169 fps mean against v2's 34–46; the shader warp within 0.0034/255 of a CPU warp of the same geometry; and the extension at rest 0.0001/255 from the page built without it. ?warp=0 is V1 exactly; ?bench=1 scrubs the uniform by hand. Numbers in tools/morph-lab/captures/v3/RESULTS.txt.

Driving guide

The three prototypes are built and self-verified. What's left is aesthetic — judgment calls only a human eye can make. Drive each page from the links below, then work the checklist underneath.

v0 — minimal harness

Buttons, duration, and easing controls over a bare split/merge value-morph on the OA basis.

Morph proven to slide, not snap: mid-flight progression 33.8% → 73.3% → 98.0%, endpoints land ≤1 px off, plateau (OA painted with borough values vs. the true borough map) MAD 0.045/255.

Zooming mid-morph in v0 (only) restarts the transition — v0 predates the polyData fix that v1 carries. Judge that behaviour in v1, not v0.

v2 — boundary warp, ward↔borough

Wards crack apart out of a borough block and heal back, instead of a value-only morph.

deck.gl's built-in position transitions BLANK the layer outright (repro preserved at ?postrans=1). The CPU-driven warp works instead: ~25–46 fps, but outlines and values can't move together, so the choreography plays as three separate beats (crack → values → heal).

v2/ · v2/?postrans=1

v3 — the warp on the GPU, as one gesture

The same crack-and-heal as v2, but the displacement happens in the vertex shader, so the values can move while the seams are open. Borough→ward and ward→borough are one continuous gesture; every other pair keeps V1's morph untouched.

Spike verdict POSITIVE. Injection point: vs:DECKGL_FILTER_GL_POSITION — the only one of deck.gl's four declared hooks that can reach position. Concurrency proven against staged references carrying the same crack: at the envelope's peak the geometry is 99.8% displaced and the values are 30% across in that same frame, where v2's CPU path left them at 29% by the 84% mark. Endpoints: split 0.0004/255, merge 0.0000/255; zero WebGL errors anywhere; every committed frame passes an ink gate, because v2 spent a sprint with a blank map and a clean error count.

Frame rate ~169 fps mean against v2's 34–46 — but the worst frame in a beat measured 50–60 ms in the driver run (8–11 ms in isolated probes), so the mean hides a stall that has not been chased down. Read the report's concerns before treating this as a 60 fps result.

?warp=0 takes the extension out entirely and is asserted pixel-identical to v1 on the same route. ?bench=1 puts a slider straight onto the uniform. ?cpuwarp=0.92 is the CPU ground truth the shader is measured against; ?stage=plateau holds the ward layer at the borough plateau.
