Crime map workbench

Prototype workbench for the merged wards↔hexes London crime chart — the two shipped charts (ward skylines, hex hotspots) rebuilt as ONE page with a tier switch, server-side hex data, and per-hex animated transitions the old GPU-aggregated HexagonLayer could never do.

STATUS — 2026-08-20. v1 lab is up. The data pipeline (server-side pointy-top hex binning in BNG, 3 zoom bands, 8 police.uk metrics × 6 periods, plus the ward skyline data passed through untouched) verified 51/51 against DuckDB and reconciles the shipped hotspot chart's totals to zero delta. v1 below is the first merged page: ward tier is the shipped skyline v4 behaviour transplanted; hex tier is NEW — a ColumnLayer over the server roster, so metric and year switches ease per-hex (the old chart re-binned client-side and could only sink-and-swap the whole field, and had no years at all). Band changes and tier changes use the sink→swap→rise ease. Everything here is throwaway lab work: unlinked, noindexed, nothing on the live site depends on it.

STATUS — 2026-08-20 (later). ss1 lab is up. One hex map that toggles between stop-and-search intensity and crime on the SAME grid — "is police activity concentrated where crime is?". Searches and crime live on different rosters, so the page merges them into a client-side UNION roster per band; every switch (search↔search, crime↔crime, search↔crime) then eases per-hex, so you see the towers move between where crime is and where searches happen. Smoke 8/8 PASS incl. a cell-value honesty leg against the raw JSON. Data caveats (8% unmapped searches pre-Oct-2024, missing Met Nov 2022, anonymised snap points) are in the page's "About this data" footer.

STATUS — 2026-09-01. chart3 SHIPPED, lab kept. The compact layout is now on the live crime chart. Unlike chart2, this page is not retired: it carries no implementation of its own — it inlines the working-tree engines and is rebuilt by build_lab.py — so there is nothing here to drift out of step, and it does one thing the live page cannot, which is force a layout the device would not choose. It stays as the device workbench. What it was for is below.

STATUS — 2026-09-01 (earlier). chart3 lab went up. The live crime chart on a phone. Measured at 390px before any of this: the card stood 1474px tall — 803px of menu under a 177px chart, four times the chart, with neither fitting on a screen with the other — and the chart's own axis labels rendered at 5.4 CSS px, because a 760-unit viewBox scaled down to 313px scales its type down with it. chart3 carries both fixes: the chip menu becomes two native <select>s, and a compact chart stops scaling altogether — its viewBox takes the plot's true pixel width, so 13px type renders at 13px and the years drop their century rather than tipping to 45 degrees. Turned sideways the menu stands beside the chart instead. Card now 770px portrait, 483px landscape, axis text 13.0px. Tablets, desktops and the wide menu are untouched.

STATUS — 2026-09-01. chart2 SHIPPED, lab retired. The two-tier menu is now the live crime chart — 63 crime types across 13 categories, against the old flat 20. The lab page is gone rather than left to rot: it carried its own copy of the menu, and a second implementation that nobody rebuilds is exactly the drift this project keeps guarding against. What it was for is recorded below.

STATUS — 2026-08-31. chart2 lab was up. A candidate replacement for the category selector on the live 2D crime chart. The flat row of 20 chips becomes two tiers — 13 categories (9 pinned + “More”) over that category’s crime types — carrying 60 categories and 120 datasets against the live chart’s 20 and 40. Every parent’s figure is the sum of the crime types shown beneath it, asserted at build time for all 13; the extras that must NOT be added sit fenced in an “also” box, split by whether they are already inside the total (rape at knifepoint is part of rape) or counted elsewhere (bicycle theft is counted under theft). Category changes ease the pills on the same 750ms cubic clock as the bars. The page carries its own copies of the chart engines, so nothing on the live chart depends on it or is changed by it.

  • chart3/ — the compact layout for phones. Useful params: ?mode=portrait · ?mode=landscape · ?mode=wide — each pins one layout, so a desktop can be shown the phone's menu and a phone the desktop's. The readout at the top of the page names the mode it picked, the card and plot widths, and the size the axis text is actually rendering at. Eye checklists are on the page itself.
  • v1/ — the merged chart. Useful params: ?tier=hexes · ?tier=hexes&mode=street · ?hud=1 (fps + state overlay) · ?radius=220|120|70 (pin a hex band, disables zoom bands) · ?m=<metric>&y=<year|all>
  • ss1/ — stop and search vs crime, hex-only. Useful params: ?m=tfp · ?m=searches_drugs&y=2023 · ?mode=street · ?hud=1 · ?radius=220|120|70. Metrics: searches_all searches_drugs searches_weapons positive_all + the 8 crime keys.
  • chart2/ — two-tier category menu, now shipped to the live chart. Things to try on a phone: the “More” chip (it takes the chosen category’s name when you pick one from behind it) · the ⓘ definitions toggle, then tap any chip to read what it counts · the download button, top right · category changes on Sexual offences, the one category whose “also” box holds both kinds at once.
